Build a catalog from one folder

Install the published Skill with GitHub CLI, or run the builder from a clone of this repository. The build_catalog.py command below is the one that stays offline; it reads no GitHub and does not wait for missing Chinese descriptions.

gh skill install mianbaofang/agent-skill-catalog agent-skill-catalog --pin v0.4.0 --agent codex --scope user gh skill install mianbaofang/agent-skill-catalog agent-skill-catalog --pin main --agent codex --scope user python skills/agent-skill-catalog/scripts/build_catalog.py --root "/path/to/skills" --output-dir "/path/to/catalog-output" --no-github-discovery --no-github-images

Installing with gh fetches the Skill from GitHub by design. The first command pins the current tagged release, v0.4.0. The second pins main, which tracks the latest source between releases and is intended for development.

Boundaries, stated plainly

What it does, and what it does not

Does the catalog modify or execute scanned Skills?

The build is read-only: it reads only the roots you supply and writes generated JSON, cached previews, and manual image overrides to the selected output directory. There is one exception to read-only browsing, and it is opt-in: the optional local server can permanently delete a top-level standalone Skill directory from the source, but only after you set allow_delete to true for that root and confirm the full Skill name. There is no sync or auto-install.

Is a default build offline?

Not guaranteed. Without flags, the builder may send Skill names to GitHub repository search and fetch one public preview per observed repository. Add --no-github-discovery --no-github-images for a build with no GitHub request, and description_queue.py next --no-github-readmes when running the description queue.

What does the search actually match?

Substring matching over Skill names, descriptions, GitHub metadata, and source-relative paths. It is not semantic or natural-language search, and it does not rank which Skill is best for a request.

Can it distinguish a plugin from a standalone Skill?

Yes, when the configured roots and package evidence make that distinction observable. Plugin aggregates get their own view and are not counted as standalone Skills.

What is the difference between quick preview and enriched?

A quick preview builds and shows entries even with missing Chinese descriptions. Adding --require-complete-descriptions makes the build exit with code 3 until the description queue is empty; exit code 0 plus pending_description_count of zero means the enriched catalog is complete.

Which language is the generated interface?

The generated catalog interface is currently Chinese. This site and the repository README are available in English and Chinese; that does not make the generated UI bilingual.
