01 / 复杂的 Skill 库

Skill 越来越多，查找也越来越困难。

主 Skill、子 Skill、插件和图片散在不同目录里。清单能列出名字，却看不出归属、调用方式和分类依据。

目录把归属、分类依据和调用方式放在一起，打开条目就能看到。
视觉与图片同类名称很多，边界不清
hyperframes主 Skill 与子 Skill 混在一起
插件缓存携带多个 Skill，需要单独显示
图片来源分类封面不能代替 Skill 预览
02 / Read-only pipeline

先确定扫描范围，再生成目录。

扫描器只读取传入的根目录，结果保留来源和中间判断。

INPUT传入根目录Skill 根目录
插件缓存根目录
READ读取 SKILL.md说明、manifest、来源路径和本地图片
REASON整理关系分类候选、家族关系、插件归属、图片状态
OUTPUT生成目录catalog.json + 自包含 index.html
不安装不执行GitHub 预览受限缓存默认隐藏绝对路径
