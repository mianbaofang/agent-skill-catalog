跨目录清点 Skill 与插件

当库里的内容不再只放在一个目录，平铺列表就回答不了一个有用的问题：这是独立 Skill、某个更大家族的子项，还是插件携带的能力？这篇教程把多个根目录扫描进同一份目录，并教你怎么读它给出的分组。

需要 Python 3.10+ · 从仓库根目录运行 · 阅读英文版

你会得到什么

一份覆盖你指定全部根目录的本地目录，三种区别清楚可见，而不是被压平：

  • 独立 Skill — 自成一体，各自来自自己的 SKILL.md。
  • 家族 — 一个主条目，详情里列出它的子 Skill；之所以聚合，是因为它们共享可观察到的主入口。
  • 插件 — 由插件缓存提供的 Skill，在独立视图里按服务商和插件名分组，不计入独立 Skill 数量。

第 1 步：指定每个根目录，并标记插件缓存

扫描两个根目录最简单的办法是重复 --root。下面的例子同时使用离线生成 Skill 目录里的离线开关。

Bash

python skills/agent-skill-catalog/scripts/build_catalog.py \
  --root "/path/to/skills" \
  --root "/path/to/plugin-cache" \
  --output-dir "/path/to/catalog-output" \
  --no-github-discovery \
  --no-github-images

PowerShell

python skills/agent-skill-catalog/scripts/build_catalog.py `
  --root "C:\path\to\skills" `
  --root "C:\path\to\plugin-cache" `
  --output-dir "C:\path\to\catalog-output" `
  --no-github-discovery `
  --no-github-images

想要可复用的配置，可以改用配置文件，它还能把每个根目录标成 skill 或 plugin 并命名。以你平台对应的示例文件为起点，references/catalog-config.posix.example.json 或 references/catalog-config.windows.example.json，再用 --config 传入：

{
  "roots": [
    {"path": "/path/to/skills", "label": "Skills", "kind": "skill"},
    {"path": "/path/to/plugin-cache", "label": "Plugins", "kind": "plugin"}
  ],
  "output_dir": "/path/to/catalog-output"
}

预期结果。 退出码 0，目录同时覆盖两个根目录。来自插件根目录的条目出现在插件视图里，而不是抬高独立 Skill 的数量。

第 2 步：读懂重复安装、同名冲突与家族

这三种情况在文件浏览器里看起来很像，含义却不同。目录会把它们区分开：

情况目录如何呈现
有证据的重复安装由同一已确认 GitHub 仓库和同名 Skill 支撑的副本合并成一个条目，而每个来源位置都在详情里保留为证据。
同名冲突两个 Skill 可以同名却来自互不相关的发布者。缺少共享仓库证据时，它们会保持为独立条目，不会被合并。
主子家族嵌套的 SKILL.md 会归到可观察到的主入口之下，呈现为一个主记录，详情里列出子项。只有当兄弟条目自己的来源说明写明了明确的产品归属或路由关系时才会并入家族；松散的关键词提及保持独立。

归并是保守的。 当证据不足以支持合并时，目录会让条目保持独立，并在分类不确定时标记复核。你能看到的家族或重复，都是扫描确实能支撑的。

第 3 步：保持清点只读

生成清点不会写入你的根目录。生成的 JSON、缓存预览图和手工图片覆盖全部进入你指定的输出目录。有两个边界值得明确说明：

  • 不同步、不自动安装、不自动删除。 目录只报告它发现的内容，不会跨机器调和副本、安装或卸载 Skill，也不会整理你的文件夹。
  • 可选删除能力属于本地服务，且默认关闭。 只有通过 allow_delete 对某个根目录显式启用后，它才可能在确认完整 Skill 名称后永久删除一个顶层独立 Skill 目录。家族和插件条目被排除，它删除的也不是根目录配置。只想浏览时，请保持关闭。

排错

现象可能原因与处理
插件缓存条目被算进独立 Skill该根目录没有被标记为插件。在配置文件里用 kind: "plugin" 传入，或者检查 --root 是否指向插件缓存而不是混进了 Skills 根目录。
你预期合并的两个条目保持独立它们缺少共享的仓库证据，或本地内容不同。这是有意为之：没有匹配证据时，目录不会猜测两个同名 Skill 是同一个。
主 Skill 和子 Skill 显示为独立条目主 Skill 没有可观察到的主入口，或子项没有声明关系。想让它们聚合，可以使用显式的整理覆盖。
扫描到了你不想扫描的目录只有你传入的根目录会被遍历。检查 --root 和 --config 参数；构建器不会向上遍历父文件夹。
