生成完全离线的 Skill 目录

你的 Skill 库里可能有私人提示词、客户项目或内部工具。这篇教程生成一份完全不发出 GitHub 请求的目录，然后解释一次构建可以被称作完成的两种方式，以及如何避免把绝对路径写进输出。

需要 Python 3.10+ · 从仓库根目录运行 · 阅读英文版

为什么默认构建不是离线

不加任何参数的构建可能通过三种方式联网。它们都不是生成可用目录的必要条件，但如果你想完全断网，每一个都需要单独的开关：

联网读取离开本机的内容开关
仓库发现把 Skill 名称作为 "<name>" in:name 查询发送到 GitHub 仓库搜索接口，为还没有仓库元数据的条目寻找候选仓库。--no-github-discovery
预览图对已确认的仓库，从允许的 GitHub 域名抓取一张公开预览图。--no-github-images
README 证据补齐缺失中文说明时，抓取公开 GitHub README 片段作为证据。description_queue.py next --no-github-readmes

GitHub 读取仅使用 HTTPS、限制域名并限制大小。如果设置了 GH_TOKEN 或 GITHUB_TOKEN 环境变量，或者你已经用 GitHub CLI 登录，这些读取会复用现有凭据，目录不会保存它。

第 1 步：生成离线目录

从仓库根目录运行，把两个路径换成你真实的 Skill 文件夹和一个空输出文件夹。这两个参数一起就能生成一份不发出任何 GitHub 请求的目录。

Bash（macOS、Linux、Windows Git Bash）

python skills/agent-skill-catalog/scripts/build_catalog.py \
  --root "/path/to/skills" \
  --output-dir "/path/to/catalog-output" \
  --no-github-discovery \
  --no-github-images

PowerShell（Windows）

python skills/agent-skill-catalog/scripts/build_catalog.py `
  --root "C:\path\to\skills" `
  --output-dir "C:\path\to\catalog-output" `
  --no-github-discovery `
  --no-github-images

预期结果。 退出码 0，输出文件夹里有 catalog.json 和自包含的 index.html。全程没有发出 GitHub 请求。打开 index.html 即可浏览和搜索。

第 2 步：选择你的完成状态

一次构建可以用两种不同的方式报告成功，你需要哪种很重要：

状态如何得到成功的含义
快速预览上面的命令，不加 --require-complete-descriptions。退出码 0。中文说明缺失的条目也会出现，可以立即浏览。
完整目录追加 --require-complete-descriptions。退出码 0 且 pending_description_count 为 0。退出码 3 表示中文说明仍在补齐 — 这是门槛在起作用，不是崩溃。

完整状态由 Agent 驱动。如果你希望目录完整、但不要 GitHub README 证据，可以保留离线参数，只让 Agent 依据本地 SKILL.md 内容补写说明：

“离线”的边界。 这些开关只是让 Python 脚本不发出 GitHub 请求，并不约束调用它的 Agent 自己的模型调用：负责写中文说明的 Agent 可能把本地 SKILL.md 文本发送到它使用的模型服务商，受该服务商自身规则约束。这里的“离线”指“目录构建不读取 GitHub”，不是对会话里所有工具的保证。

Bash

python skills/agent-skill-catalog/scripts/description_queue.py next \
  --root "/path/to/skills" \
  --output-dir "/path/to/catalog-output" \
  --no-github-readmes

PowerShell

python skills/agent-skill-catalog/scripts/description_queue.py next `
  --root "C:\path\to\skills" `
  --output-dir "C:\path\to\catalog-output" `
  --no-github-readmes

Agent 写完一批中文说明并用 description_queue.py apply 保存后，用 --refresh --require-complete-descriptions 连同两个离线参数 一起重建，直到队列清空。每一次重建都要重新带上离线参数；漏掉就会在下一次构建允许 GitHub 请求：

Bash

python skills/agent-skill-catalog/scripts/build_catalog.py \
  --root "/path/to/skills" \
  --output-dir "/path/to/catalog-output" \
  --refresh \
  --require-complete-descriptions \
  --no-github-discovery \
  --no-github-images

PowerShell

python skills/agent-skill-catalog/scripts/build_catalog.py `
  --root "C:\path\to\skills" `
  --output-dir "C:\path\to\catalog-output" `
  --refresh `
  --require-complete-descriptions `
  --no-github-discovery `
  --no-github-images

进度保存在 catalog-curation.json，可以中断后续跑。Python 脚本不会暗中调用模型，也不需要模型密钥。

第 3 步：分享前先确认输出里有什么

生成的页面是一个自包含 HTML 文件。请把它当作你 Skill 库元数据的一份副本，而不是自动可以公开的东西：

  • 绝对路径默认隐藏。 条目使用来源相对路径。--include-absolute-paths 是明确的本地诊断开关；打算分享的目录绝不要使用它。
  • 隐藏绝对路径不等于移除私密内容。 Skill 名称、说明、相对来源路径和 GitHub 链接仍然描述着你的库。分享前请自己检查 catalog.json 和渲染出来的页面。
  • 本地图片可能被内嵌。 自包含页面可能内嵌你磁盘上存在的 Skill 自带图片，所以离线构建并不保证输出文件不含敏感内容。
  • 缓存预览图留在输出文件夹里。 使用 --no-github-images 时没有抓取的预览图；你手工保存的图片会写入同一输出目录下的 curated-images/。

以后刷新，仍然离线

安装新 Skill 后，用同样的 --root 和 --output-dir 重跑同一条构建命令。如果输出文件夹已经存在，构建器会拒绝替换并报错退出；确认目标文件夹里是可重新生成的目录后，再加 --refresh 重跑。

排错

现象可能原因与处理
完整构建返回退出码 3不是崩溃。中文说明仍在补齐。运行说明队列，或者去掉 --require-complete-descriptions 接受快速预览。
构建器报错与输出目录有关该文件夹已经存在。确认里面是愿意重新生成的目录后，加 --refresh 重跑。
部分条目的图片显示 missing evidence离线时这是正常的。没有抓取 GitHub 预览图，这些条目就没有图片证明。这个标签是诚实的；生成的分类封面不会被当成 Skill 专属图片展示。
构建仍然访问了 GitHub构建器需要同时有 --no-github-discovery 和 --no-github-images。README 证据的开关是独立的，位于 description_queue.py next。
