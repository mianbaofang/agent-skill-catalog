Task guide

Build an offline skill catalog

Your Skill library may hold private prompts, client work, or internal tooling. This guide builds a catalog with no GitHub request at all, then explains the two ways a build can be called complete and how to keep absolute paths out of the output.

Needs Python 3.10+ · Runs from the repository root · Read in Chinese

Why a default build is not offline

A build with no extra flags can touch the network in three ways. None of them are required to produce a working catalog, but each one needs its own switch if you want zero network activity:

Network readWhat leaves your machineSwitch
Repository discoverySkill names are sent to the GitHub repository search API as "<name>" in:name queries to find candidate repositories for entries with no repository metadata yet.--no-github-discovery
Preview imagesFor observed repositories, one public preview image is fetched from allowlisted GitHub hosts.--no-github-images
README evidencePublic GitHub README excerpts are fetched as evidence while filling missing Chinese descriptions.description_queue.py next --no-github-readmes

GitHub reads are HTTPS-only, host-allowlisted, and size-limited. If a GH_TOKEN or GITHUB_TOKEN environment variable is set, or you are signed in with the GitHub CLI, that existing credential is reused for these reads and is never stored in the catalog.

Step 1: Build the offline catalog

Run from the repository root. Replace the two paths with your real Skill folder and an empty output folder. These two flags together produce a catalog with no GitHub request.

Bash (macOS, Linux, Windows Git Bash)

python skills/agent-skill-catalog/scripts/build_catalog.py \
  --root "/path/to/skills" \
  --output-dir "/path/to/catalog-output" \
  --no-github-discovery \
  --no-github-images

PowerShell (Windows)

python skills/agent-skill-catalog/scripts/build_catalog.py `
  --root "C:\path\to\skills" `
  --output-dir "C:\path\to\catalog-output" `
  --no-github-discovery `
  --no-github-images

Expected result. Exit code 0, with catalog.json and a self-contained index.html in the output folder. No GitHub request is made. Open index.html to browse and search.

Step 2: Choose your completion state

A build can report success in two different ways, and it matters which one you need:

StateHow you get itWhat success means
Quick previewThe command above, without --require-complete-descriptions.Exit code 0. Entries with missing Chinese descriptions still appear, so you can browse immediately.
Enriched catalogAdd --require-complete-descriptions.Exit code 0 and pending_description_count equal to zero. Exit code 3 means Chinese descriptions are still pending — the gate is working, not crashing.

The enriched state is what an agent drives. If you want a complete catalog without GitHub README evidence, keep the offline switches and let the agent fill descriptions from local SKILL.md content only:

Scope of "offline". These switches stop the Python scripts from making GitHub requests. They say nothing about the invoking Agent's own model calls: an Agent that writes Chinese descriptions may send local SKILL.md text to its model provider under that provider's own rules. Treat "offline" here as "the catalog build reads no GitHub", not as a guarantee about every tool in your session.

Bash

python skills/agent-skill-catalog/scripts/description_queue.py next \
  --root "/path/to/skills" \
  --output-dir "/path/to/catalog-output" \
  --no-github-readmes

PowerShell

python skills/agent-skill-catalog/scripts/description_queue.py next `
  --root "C:\path\to\skills" `
  --output-dir "C:\path\to\catalog-output" `
  --no-github-readmes

After the agent writes a batch of Chinese descriptions and applies it with description_queue.py apply, rebuild with --refresh --require-complete-descriptions together with the two offline switches, until the queue is empty. Every rebuild needs the offline flags again; omitting them would allow a GitHub request on the next build:

Bash

python skills/agent-skill-catalog/scripts/build_catalog.py \
  --root "/path/to/skills" \
  --output-dir "/path/to/catalog-output" \
  --refresh \
  --require-complete-descriptions \
  --no-github-discovery \
  --no-github-images

PowerShell

python skills/agent-skill-catalog/scripts/build_catalog.py `
  --root "C:\path\to\skills" `
  --output-dir "C:\path\to\catalog-output" `
  --refresh `
  --require-complete-descriptions `
  --no-github-discovery `
  --no-github-images

Progress is resumable from catalog-curation.json. The Python scripts never call a hidden model and need no provider key.

Step 3: Decide what the output contains before you share it

The generated page is a single self-contained HTML file. Treat it as a copy of your library's metadata, not as automatically safe to publish:

  • Absolute paths are redacted by default. Entries carry source-relative paths. --include-absolute-paths is a deliberate local diagnostic; never use it for a catalog you plan to share.
  • Redaction is not the same as removing private content. Skill names, descriptions, relative source paths, and GitHub links still describe your library. Inspect catalog.json and the rendered page yourself before sharing anything.
  • Local images can be embedded. A self-contained page may inline Skill-provided images that exist on your disk, so an offline build does not guarantee a sensitive-output-free file.
  • Cached previews stay in the output folder. With --no-github-images there are no fetched previews; manual images you save are written to curated-images/ in the same output directory.

Refreshing later, still offline

After installing new Skills, re-run the same build command with the same --root and --output-dir. If the output folder already exists, the builder refuses to replace it and exits with an error; re-run with --refresh only after you have checked that the target folder holds a generated catalog you are willing to regenerate.

Troubleshooting

SymptomLikely cause and fix
Exit code 3 on the enriched buildNot a crash. Chinese descriptions are still pending. Run the description queue, or drop --require-complete-descriptions to accept a quick preview.
Builder exits with an error about the output directoryThe folder already exists. Confirm it holds a catalog you want regenerated, then re-run with --refresh.
Some entries show missing evidence for imagesExpected offline. No GitHub preview was fetched, so there is no image proof for those entries. The label is honest; a generated category cover is never shown as a Skill-specific image.
A build still reached GitHubBoth --no-github-discovery and --no-github-images are required for the builder. The README-evidence switch is separate and lives on description_queue.py next.
