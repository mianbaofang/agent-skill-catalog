Task guide

Search the agent skills you already installed

You remember installing something for a job, but not its name or which folder it sits in. This guide picks one explicit root, builds a local catalog, searches it, and opens the entry that tells you how to invoke it and where it came from.

Needs Python 3.10+ · Runs from the repository root · Read in Chinese

Before you start

You need the folder path where your Skills actually live. Agent Skill Catalog does not guess this for you: it scans only the root you hand it. Different agents and install methods put Skills in different places, and you may have chosen a custom folder, so treat the locations below as examples to check on your own machine rather than fixed defaults.

  • One folder that contains Skill subfolders, each with a SKILL.md inside.
  • Python 3.10 or newer to run the builder.
  • The commands below run from the repository root, so clone or download the project first.

Choosing a path. If you installed a Skill with gh skill install ... --agent codex --scope user, the Skill was placed in the user scope for that agent. Confirm the exact folder on your system before scanning it. The examples below use placeholder paths on purpose.

Step 1: Build a catalog from one root

Replace /path/to/skills with the folder you confirmed and /path/to/catalog-output with an empty folder for the results. These flags keep the first build fully offline.

Bash (macOS, Linux, Windows Git Bash)

python skills/agent-skill-catalog/scripts/build_catalog.py \
  --root "/path/to/skills" \
  --output-dir "/path/to/catalog-output" \
  --no-github-discovery \
  --no-github-images

PowerShell (Windows)

python skills/agent-skill-catalog/scripts/build_catalog.py `
  --root "C:\path\to\skills" `
  --output-dir "C:\path\to\catalog-output" `
  --no-github-discovery `
  --no-github-images

Expected result. Exit code 0, and the output folder now contains catalog.json and a self-contained index.html. Because this command omits --require-complete-descriptions, entries are shown even when their Chinese description has not been filled in yet; you can browse and search immediately.

Step 2: Search by name, description, or path

Open index.html in a browser and type into the search box. The current search is substring matching over Skill names, descriptions, GitHub metadata, and source-relative paths, then you can filter by category or view. Search a name you can partially remember, such as skill-catalog, or a word you know appears in a description.

Expected result. The list narrows to entries whose matching field contains that substring. Searching an exact Skill name such as agent-skill-catalog returns that one card.

What this search is. It is literal substring matching over names, descriptions, and source paths. It is not semantic or natural-language search, and it does not rank which Skill is best suited to a request. A word that appears only in your own intent, and nowhere in a name, description, or path, will not match.

Step 3: Open the entry to see how to invoke it

Click a result card to open the detail view. That panel is where the catalog earns its keep. It shows:

  • The invocation text, so you can phrase the request to your agent correctly.
  • The source location, meaning the relative path of the SKILL.md that produced the entry.
  • Category candidates with confidence, and a review flag when classification was uncertain.
  • An observed GitHub repository link when local or package evidence supports one, or a missing evidence label when it does not.

Once you have the invocation wording, you can ask your agent to use that Skill by name in the next session.

Multiple roots, and picking a different folder next time

Pass --root once per folder to scan several roots in a single catalog. To rescan after installing a new Skill, re-run the same command with the same --root and --output-dir. If the output folder already exists, the builder refuses to replace it and exits with an error; re-run with --refresh only after you have checked that the target holds a generated catalog you are willing to regenerate. See Inventory skills and plugins across folders for labeling one root as a plugin cache.

Troubleshooting

SymptomLikely cause and fix
The catalog is empty, or has one unrelated entryThe --root path does not point at a folder whose subfolders each contain a SKILL.md. Check the path, then point it at the parent folder that holds the Skill folders.
A command is not foundRun from the repository root so the relative path to skills/agent-skill-catalog/scripts/build_catalog.py resolves, and confirm python --version is 3.10 or newer.
Entries have empty or missing descriptionsExpected for a quick preview. Add --require-complete-descriptions to enter the enriched flow described in Build an offline skill catalog.
You expected an offline build but saw GitHub activityThe first build only stays offline with both --no-github-discovery and --no-github-images. Omitting either one allows a GitHub request.
